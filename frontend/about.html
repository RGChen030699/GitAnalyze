How it works

GitAnalyze reads public GitHub data and explains it in plain language, so you can tell whether a repository is alive, maintained and safe to depend on. We show evidence and the rule behind it, never a score.

How to use it

  1. Find a repository

    Type a name in the box on the home page, or paste a link. Each of these works:

    https://github.com/owner/repogithub.com/owner/repo/issues/12owner/repogit@github.com:owner/repo.gitagent

    Paste up to three, separated by spaces, commas or new lines. Compare up to 3 repositories at a time.

  2. Browse the rankings

    The table under the search box lists the repositories we track.

    • Rank by Total stars (the default), Gaining stars, or Trending.
    • Gaining stars lets you pick this week, this month or this year.
    • Filter by language, status and AI capabilities. Archived repositories are hidden unless you turn them on.
    • Show 25, 50 or 100 at a time, then keep scrolling for more.

  3. Open a report

    Click a repository name. The report answers first, then shows the evidence.

    • Summary: status, the checks behind it, a decision brief and the key numbers.
    • Evidence: momentum, maintenance, people, issues and pull requests, releases, peers, and AI and trust.
    • Every number has an info button that says what it means, how it’s worked out, where it comes from and what it can’t tell you.

  4. Compare options

    Press the plus button on up to three rows in the table. They collect in the compare bar at the bottom of the screen. Press Compare to line them up together in the table.

  5. Share what you found

    • Copy brief puts a short summary, with the source and date, on your clipboard for a slide, doc or message.
    • Download CSV gives you the weekly numbers behind the charts.
    • Every report has its own link, /repo/owner/name, so you can send it to your team.

Status and checks

Each repository gets one status from a fixed rule. Archived wins over everything else.

StatusRule
ActiveA commit in the last 30 days, and a release in the last 182 days or no releases ever
SlowingA commit in the last 182 days, but not Active
QuietNo commit in the last 182 days
ArchivedThe owner archived it on GitHub. It is read-only.

Under the status, the report lists the checks it is based on. Each one passes, asks you to look, or stops you.

CheckPassLook firstStop
MaintenanceActively maintainedMaintenance is slowingNo recent work, or archived by its owner
MaintainersShared maintenanceMostly one person: one account made 80% or more of last year’s commitsN/A
LicenseA standard license, such as MITCustom or unrecognized licenseNo license: others may not legally reuse this code
Star patternSteady interestUnusual spike: lots of new stars but little other activityN/A
Scripts in skillsNo skills run scriptsSome skills include scripts that can run on your computerN/A

Decision brief rules

The decision brief answers five questions with fixed rules. No AI writes it: the same numbers always give the same words.

QuestionComparesAnswers
Is interest real and growing?Stars in the last 30 days against the 30 days beforeGrowing (up more than 10%), Cooling (down more than 10%), Steady, Fading (no net stars), or Spiky when the star-pattern check fires
Is someone still working on it?Commits in the last 13 weeks against the 13 beforeSpeeding up (up more than 10%), Slowing down (down more than 40%), Steady, or Stopped (none)
Will my bug reports get answered?Issues closed for every issue opened, last 6 monthsKeeping up (95% or more), Falling behind (60–95%), Not answering (under 60%)
Does it ship on a rhythm?Days since the last release against its usual gapOn its usual pace (up to 1.5× the gap), or Overdue
What if one person leaves?The top contributor’s share of last year’s commitsShared by N people, or Depends on one person (80% or more)

The thresholds are the team’s current working values and may change after user interviews.

Finding AI capabilities

We check each repository’s file tree with four rules. Higher levels are stronger evidence. We never show a quality score or a ‘safe’ label.

LevelWhat we look forConfidence
1. AI skillA file named SKILL.md with a valid header and a descriptionHigh
1b. Possible skillSKILL.md without a valid header, or inside a template, example or test folderMedium
2. Set up for AI coding agentsFiles such as CLAUDE.md, AGENTS.md, GEMINI.md, Cursor rules or Copilot instructionsMedium
3. MCP serverA server.json using the MCP schema, or an MCP library in the project’s dependenciesMedium
4. README mentions AI featuresPhrases such as “agent skill” or “MCP server” in the README. A hint, not proof.Low

When a skill folder contains script files, we say so: this skill includes scripts that can run on your computer. Read them before installing.

What rankings cover

Rankings cover the repositories we track, not all of GitHub. The watch list is built from:

  • the most-starred repositories on GitHub,
  • repositories on GitHub Trending, read through the GitHubTrendingRSS feed and credited “From GitHub Trending”,
  • repositories tagged with AI topics,
  • and any repository someone looks up here.

Rankings refresh once a day. Gaining stars covers this week, this month or this year. We don’t offer 5- or 10-year windows.

Known limits

  1. Stars are not usage. GitHub has no data on how many people use a project.
  2. Net stars. Removed stars disappear from past weeks too, so history can shift slightly.
  3. Rankings cover our watch list: top repositories by stars, GitHub Trending, AI topics, and repositories users have looked up. Not every repository on GitHub.
  4. Contributor details cover the top 100 contributors only.
  5. AI capabilities are found by file rules; a skill in a non-standard format may be missed. We do not judge quality.
  6. Updated daily, not in real time.
  7. Not covered: company backing, security advisories, paid support, documentation quality.

Glossary

Star
A bookmark someone adds to a repository on GitHub. It shows interest, not use.
Fork
A personal copy of a repository that someone can change without touching the original.
Release
A named version the maintainers published, usually with notes on what changed.
Tag
A label on one point in the history. A tag, not a formal release, unless the maintainers publish it as one.
Issue
A bug report, question or request someone opened on the repository.
Pull request
A proposed change someone asks the maintainers to add.
Contributor
An account that has made commits to the repository.
Archived
Made read-only by the owner. No one will fix bugs or answer issues.
License
The terms that say whether, and how, others may reuse the code.
Maintainer
A person who reviews changes, answers issues and publishes releases.
AI skill
A folder with a SKILL.md file that teaches an AI assistant to do a task.
MCP server
A tool that AI apps can connect to, using the Model Context Protocol.
Agent setup file
A file such as CLAUDE.md or AGENTS.md that tells AI coding agents how to work in the repository.
